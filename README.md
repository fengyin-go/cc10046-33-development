# 网络数据采集与RPA自动化平台

面向网页数据采集、自动化流程编排、解析规则管理、代理池调度与采集结果校验的数据采集工程平台

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/WorkbenchView.vue|tsx  全部模块共享工作台
│   ├── src/data/modules.ts              18个业务模块配置
│   ├── src/api/              统一请求封装
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/resource.py  通用查询/导出/登记/动作接口
│   ├── app/services/<key>.py    每个模块独立领域逻辑
│   ├── app/services/base.py     共享服务骨架
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8010/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5174/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8010`。

## 约定

- 全部模块共享`frontend/src/views/WorkbenchView.vue|tsx`和一套资源路由。
- 每个模块仍保留独立`backend/app/services/<模块>.py`；纯前端保留
  `frontend/src/domain/<模块>.ts`，用于承载真实业务差异并维持36题位容量。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 采集时间区间与批次追踪

`采集调度`与`批次追踪`之间新增按时间切分的空区间确认机制，统一走 `/api/trace/*`：

- 区间一律按半开 `[start, end)` 处理：`start == end` 是零宽区间、`start > end`
  是逆序区间，二者都「无法执行」，切分不产窗口、登记空回执返回 422；
  只有正常区间实际抓到零条，才能登记「空区间确认回执」，二者严格区分。
- 空回执（`empty_receipts`）与真实页面（`pages`）分账存放、各自可回查；
  已确认无数据的窗口下次任务不重取，同区间/同标记重复送达幂等，边界页只确认一次。
- 迟到的真实页面落入历史空回执区间时，回执转为「已被真实页更正」并使该窗口重新待办；
  页面同时带 `front_correction`（前轮更正）与 `first_valid_of_round`（后轮首条有效页）判定。
- `/api/trace/rounds/reopen` 可在另一个入口重新打开批次追踪，前轮空回执、已落库页面
  与 `/api/trace/next-task` 的剩余缺口一起回查。
- 前端 `批次追踪` 菜单指向专用控制台 `views/TraceConsole.vue`。
